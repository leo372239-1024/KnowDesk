## 1. 项目名称

**KnowDesk｜企业知识库 RAG 智能问答 Agent**（个人全栈项目）

> 备选写法：若坚持用「GraphRAG」命名，面试前必须能讲清"图"在哪。当前实现是基于标题树的层级检索 + 章节上下文扩展（`expand_siblings`），无图数据库、无实体关系抽取与图遍历——建议按上方「RAG / 层级检索」表述。

---

## 2. 项目定位

面向企业非结构化文档的 RAG 知识问答 Agent，用 LangGraph 状态机编排「查询理解 → 多路混合检索 → 证据门控 → 生成 / 拒答」，解决通用大模型在私域知识上「答得流畅但不可信」的问题，做到断言级引用可溯源、证据不足即拒答。

---

## 3. 项目业务

员工上传制度、设备手册、FAQ 等文档后，系统自动解析、PII 脱敏、结构化分块并建立三路索引；提问时返回带 chunk 级引用的答案，支持 SSE 流式输出、多轮会话与租户 / 部门 / 密级隔离；点赞点踩沉淀 Bad Case 池，联动评测集驱动策略迭代。

---

## 4. 技术栈

Python · FastAPI · LangGraph · SQLAlchemy 2.0(async) · PostgreSQL(pgvector) · Milvus · BM25 + RRF · DeepSeek · React 18 + TypeScript · Docker

---

## 5. 效果提升 / 亮点

**① 结构化分块保住表格与条款完整性**
按标题层级切块、表格独立成块并全量保留表头、条款级 chunk 继承父章节 `section_path`。相比固定长度切分，参数表不再被「腰斩」，表格类参数查询（q001–q008）准确率达 100%。

**② 三路召回 + RRF 融合 + 混合重排**
dense 向量、jieba 词级 BM25、字符 bigram BM25 并行召回后 RRF 免调权融合；自研混合重排以「query 内容覆盖度」为主信号，修掉长 chunk 下余弦被长度稀释的问题。相关 / 不相关分数分离度由 1.5x 提升至 5.2x，Recall@10 达 100%。

**③ 证据门控 + 引用硬门禁治理幻觉**
门控以原 query 的 top1 为主信号，置信度差值只加成不惩罚（避免多跳题误拒），再用实体标识符校验拦下「语料外实体」型漏拒；生成侧逐断言校验 `[chunk_id]`，无效引用确定性裁除。faithfulness 100%，refusal_correctness 0% → 100%，false_refusal 收敛至 0%。

**④ 自建评测集驱动量化迭代**
构建 50 题 Golden Dataset（含 10 道不可答）与 baseline / 改进版双跑对照，用指标定位问题而非凭感觉调参；接入真实 DeepSeek 后复盘改写偏航、短 query 阈值过严等 5 类失效并逐项修复。28 个单测覆盖分块、RRF、门控、ACL 与提示注入防御。

**⑤ 安全与多租户前置拦截（空间允许再放）**
ACL 在检索阶段前置过滤（租户 / 部门 / 密级），而非生成后脱敏；检索内容与网络内容分别以 `<untrusted_document>` / `<untrusted_content>` 包裹，隔离提示注入；PII 入库前正则脱敏，审计日志可回溯。

## 面试高概率追问（提前备好口径）

| 追问 | 一句话口径 |
|---|---|
| 证据门控阈值 0.20 怎么定的？ | 按「原 query 单独检索」的证据分布，可答题 ≥0.25、拒答题 ≤0.15，取中间安全区间，并用 50 题回归验证。 |
| 为什么还要一路字符级 BM25？ | 型号 / 编号（XG-2000A、IP54）经 jieba 分词后被打散，bigram 能保住精确匹配。 |
| 为什么 LLM 改写后仍保留原 query？ | 改写偏航时（如「紧急乘车」被改成「购票流程」）原 query 的强证据会被一并丢弃，导致可答题误拒；改为原 query 主导门控、改写仅补充召回后，false_refusal 从 10% 降到 5% 再到 0%。 |
| 100% 的指标可信吗？ | 属自建 50 题集上的结果，题目与语料同源，正确用法是看「基线 vs 改进版」的差值（如 refusal 0% → 100%），而不是绝对值。 |
